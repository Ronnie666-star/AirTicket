# 01 · PPT 提示词（给另一个 AI 用）

> 用法：把下面「PPT 提示词」整段复制给任意 AI（KIMI / 通义 / 豆包 / ChatGPT），让它生成两份 PPT 的逐页大纲与文案。
> 本文件是**你用来指挥别的 AI 的原材料**，已按课程要求（第一次：需求分析与设计 30 分；第二次：系统演示 30 分）备好全部素材。
> 提示词里的所有数字、表名、SQL 均来自本项目真实实现，可直接引用，不要让它乱编。

---

## 一、项目素材包（提示词会引用，先给你核对）

- **项目名**：AirTicket 飞机票订票系统（课程设计）
- **一句话**：一个可运行的机票订票系统，覆盖「登录 → 搜索 → 选舱订票 → 模拟支付 → 核销 → 退订 / 改签」完整交易链路，带管理后台与统计。
- **技术栈**：Spring Boot 3.2 + JDK17 + MyBatis + Flyway + MySQL 8（后端）；Vue3 + Vite + Pinia（前端）；Docker 交付。
- **三种角色**：管理员 ADMIN（初始化创建，唯一入口）、商家 MERCHANT（管理员分配）、旅客 PASSENGER（自助注册）。
- **9 张表**：`sys_user`(用户) / `airline`(航司) / `airport`(机场) / `plane`(机型) / `channel`(销售渠道) / `flight`(航班) / `orders`(订单) / `route`(实时轨迹) / `passenger`(常乘机人)。
- **演示数据规模（V6 迁移内置）**：6 航司 + 10 机场 + 10 机型 + 3 渠道 + 12 用户 + **42 个航班** + 12 条轨迹 + **66 个订单** + 14 条常乘机人 = **175 条实体数据**；关联关系（外键）约 **374 条**（订单 66×3 + 航班 42×3 + 轨迹 + 机型 + 常乘机人 14×2）。满足「实体 ≥30 条、关联关系 ≥200 条」。
- **演示账号（密码均 Pass@1234）**：旅客 `user001`~`user010`；商家 `merch01`/`merch02`；管理员 `admin01`（初始化时自设密码）。
- **3 个统计功能**（管理员）：
  1. 热门航班销量 Top10（订单数 / 成交金额 / 座舱利用率）
  2. 营收总览 + 渠道营收占比（成交总额 / 实收 / 退款 / 退票费收入）
  3. 旅客消费排行 Top10（单量 / 成交金额）
- **健壮性亮点**：订票/退票/改签全部 `SELECT ... FOR UPDATE` 行锁防超卖；两段式模拟支付（支付中 → 渠道回调/用户确认），支付失败自动回补余票，启动自愈清理"支付中"残留；删除被引用数据受保护；只查自己的订单（`WHERE id_user = ?`）。
- **易用性**：前端 Apple 风格设计系统（统一设计令牌：系统字体 / 白浅灰底 / 品牌蓝 / 圆角 / 柔和阴影 / 大留白），登录即见的分角色导航。

## 二、PPT 提示词（整段复制给 AI）

```
你是课程设计的 PPT 设计专家。请根据下面提供的真实项目信息，分别输出
【PPT A：系统需求分析与设计】和【PPT B：系统演示】两份 PPT 的逐页大纲（含每页标题、
要点文案、配图建议），每份 12~15 页，风格简洁学术、图表化，不要花哨。

【项目背景】
AirTicket 飞机票订票系统：Spring Boot 3.2 + MyBatis + Flyway + MySQL8 后端，
Vue3 + Vite 前端，Docker 交付。三种角色：管理员(初始化创建)/商家(管理员分配)/旅客(自助注册)。
功能：登录注册、航班搜索(按起降地/日期/价格/机型/机场)、三舱(头等/商务/经济)定价与订票、
两段式模拟支付(防超卖：订票/退票/改签用 SELECT...FOR UPDATE 行锁)、核销、退订退款(退票费)、
同航司同舱改签(多退少补)、实时轨迹、个人中心/常乘机人、管理后台(用户/基础数据/放票)、
3 个统计功能。演示数据：42 航班 + 66 订单 + 12 用户等共 175 条实体、约 374 条关联关系。

【PPT A：系统需求分析与设计】（对应 30 分：功能需求分析 10 / 性能等非功能需求 5 / 数据库设计 15）
第1页 封面：课程名 + 项目名 + 组员
第2页 目录
第3页 系统概述与建设目标（1 分钟讲清做什么）
第4页 用户角色与权限需求（三种角色各自能做什么，配"角色权限矩阵"表）
第5页 功能需求分析：用"用例图"展示全部功能（登录/注册/搜索/订票/支付/核销/退订/改签/轨迹/统计），
      并对每个用例一句话说明。请用 mermaid 画用例图，我放到 PPT 里。
第6页 核心业务流程：订票-支付-出票-核销-退订/改签 状态流转（配状态机图）
第7页 非功能需求：性能(常用查询索引优化、行锁防超卖)、安全(JWT无状态鉴权、BCrypt密码、
      角色权限校验@RequireRole)、健壮性(支付失败回补余票、启动自愈)、易用性(前端设计系统)
第8页 数据库设计总览：9 张表清单 + 一句话职责 + 三张 E-R 图拆分
第9页 实体-联系图(ER图)：请用 mermaid 画 ER 图，实体：航司1—N机型1—N航班N—1机场(起/降各一)；
      航班1—N订单N—1用户、N—1渠道；航班1—1轨迹；用户1—N常乘机人N—1用户。
      标注每对联系的基数(1:1 / 1:N / N:M)与参与约束。
第10页 概念设计→逻辑设计：把 ER 图转成关系模式(表名+主键+外键)，说明外键来源
第11页 逻辑设计核心表详解：flight / orders 两个核心表的字段设计(可带 3~4 行建表 SQL)
第12页 规范化分析：说明各表满足 3NF，orders 不存冗余(总价=舱价)、flight 冗余 region 的取舍理由
第13页 索引与查询优化设计：常用查询路径 → 对应索引(列)
第14页 小结与答疑页(放"谢谢聆听，请老师指正")

【PPT B：系统演示】（对应 30 分：完整业务流程 + 至少3个统计功能 16 / 健壮性 8 / 易用性 6）
第1页 封面：系统演示 + 项目名
第2页 演示环境与账号(本地/Docker 启动方式、admin01/merch01/user001 三个演示账号)
第3页 演示流程总览(一条主线：搜航班→选舱下单→模拟支付→出票→核销，穿插退订/改签)
第4页 角色演示-旅客：注册/登录 → 搜索(条件筛选截图) → 航班详情(三舱价格/余票/轨迹)
第5页 角色演示-旅客：下单 → 两段式支付(支付中→确认/渠道回调) → 我的订单(状态流转)
第6页 角色演示-商家：放票(创建航班) → 核销 → 改签(同舱多退少补)
第7页 角色演示-管理员：初始化 → 用户管理(创建商家/启禁用/重置密码) → 基础数据维护
第8页 统计功能①热门航班销量 Top10(截图+图表：销量/金额/座舱利用率)
第9页 统计功能②营收总览与渠道占比(截图：成交总额/实收/退款/退票费收入/渠道占比)
第10页 统计功能③旅客消费排行 Top10(截图)
第11页 健壮性演示：并发超卖防护(FOR UPDATE)、支付失败回补余票、航班取消批量全额退款、删除引用保护
第12页 易用性说明：前端 Apple 风格设计系统 + 分角色导航 + 错误提示友好化
第13页 演示数据规模(175 条实体 / 374 条关联关系，满足课程要求)
第14页 小结与答疑页
```

## 三、给 AI 的补充要求（选填，可追加到上面提示词后面）

1. 所有 mermaid 图请直接输出代码块，我在 PPT 里用 `mermaid.ink` 或 Typora 渲染。
2. ER 图要符合"实体—联系"规范画法：矩形=实体、椭圆=属性、菱形=联系、连线标 1/N。
3. 每页要点控制在 3~5 条短句，别整段文字。
4. 涉及数字/表名必须用素材包里给的，不要编造。
5. 两份 PPT 内容要有区分：A 讲"设计"，B 讲"成品演示"。

# 03 · 课程设计报告提示词（给另一个 AI 用）

> 用法：把下面的「报告提示词」整段复制给任意 AI，让它按**评分标准**写一份完整课程设计报告。
> 本文件是**你用来指挥别的 AI 的原材料**，已按评分标准把 9 张表结构、ER 关系、索引、SQL、功能全部备好。
> 评分标准对应：① 数据库概念设计和逻辑设计（20 分）② 数据库规划、系统定义、需求分析（15 分）③ 物理设计和其他（5 分）。

---

## 一、报告提示词（整段复制给 AI）

```
你是数据库课程设计报告写作专家。请根据下面提供的真实项目信息，写一份《飞机票订票系统数据库课程设计报告》，
约 6000~8000 字，结构严格按下面的章节，打分点对应的部分要重点展开并给出可验证的 SQL / 表结构。
语言中文，专业、完整、有条理。所有表名、字段、SQL 必须用素材里的，不要编造。

【项目一句话】
AirTicket 飞机票订票系统：Spring Boot 3.2 + MyBatis + Flyway + MySQL8 后端，Vue3 前端，Docker 交付。
三种角色：管理员(初始化创建)/商家(管理员分配)/旅客(自助注册)。功能：登录注册、航班搜索、三舱(头等/商务/经济)
定价订票、两段式模拟支付、核销、退订退款、改签、实时轨迹、管理后台、3 个统计功能。
演示数据：42 航班 + 66 订单 + 12 用户等，实体 175 条、关联关系约 374 条。

【章节与打分点】

## 第一章 数据库规划（15 分中的一部分）
1.1 系统开发背景与意义（机票线上化、防超卖、多渠道销售的现实问题）
1.2 系统可行性分析（技术/经济/操作）
1.3 系统总体结构（前后端分离 + MySQL + 三种角色的总体架构图，用文字描述即可）

## 第二章 系统定义与需求分析（15 分）
2.1 系统定义：一句话定义 + 三种角色的职责表
2.2 功能需求分析：列出 11 类功能（登录注册、航班搜索、订票、支付、核销、退订、改签、实时轨迹、
      个人中心、管理后台、统计），每个功能一句话 + 是否涉及写库
2.3 数据需求分析：从功能反推出要存哪些数据（用户/航司/机场/机型/航班/订单/渠道/轨迹/常乘机人）
2.4 性能需求：常用查询(搜索/订单/统计)走索引；写操作(订票/退票/改签)行锁 + 事务保证不超卖
2.5 安全需求：BCrypt 密码、JWT 无状态鉴权、@RequireRole 角色校验、只能查自己的订单、删除引用保护

## 第三章 数据库概念设计（20 分重点）
3.1 局部 ER 图（拆三张画/描述）：
   ER-1 航司-机型-航班-机场：航司1—N机型1—N航班N—1机场(出发/到达各一个，标注两个角色)
   ER-2 订单-用户-渠道-航班：用户1—N订单N—1渠道、订单N—1航班
   ER-3 轨迹-常乘机人：航班1—1轨迹；用户1—N常乘机人N—1用户(自关联)
3.2 每张图说明实体、属性（主键下划线）、联系类型与基数(1:1/1:N/N:M)、参与约束(部分/全部)
3.3 全局 ER 图合并原则说明（消除冲突、实体合并）

## 第四章 数据库逻辑设计（20 分重点）
4.1 ER 图转关系模式：9 个关系模式，每个给出：关系名(下划线标主键，外键用→注释)，并说明转换规则
   sys_user(id, username, password, real_name, age, email, phone, status, role, create_at)
   airline(id, name, create_at)
   airport(id, name, region, create_at)
   plane(id, id_airline→airline.id, model_name, length, wingspan, height,
         max_takeoff_weight_kg, max_landing_weight_kg, max_seat_first_class,
         max_seat_business_class, max_seat_economy_class, create_at)
   channel(id, channel_name, api_gateway_url)
   flight(id, id_plane→plane.id, id_airport_dep→airport.id, id_airport_arr→airport.id,
          code, datetime_dep, datetime_arr, region_dep, region_arr, distance,
          seat_first_class, seat_business_class, seat_economy_class,
          price, price_business_class, price_first_class, cancellation_fee, gate, status, created_by, create_at)
   orders(id, id_flight→flight.id, id_user→sys_user.id, id_channel→channel.id, code,
          cabin_class, total_price, total_tax, pay_status, order_status,
          pay_time, issue_time, cancel_time, remark, create_at)
   route(id, id_flight→flight.id, distance_remain, time_remain, altitude, speed,
         latitude, longitude, time_stamp, create_at)
   passenger(id, user_id→sys_user.id, passenger_id→sys_user.id, create_at)
4.2 规范化分析：逐表说明满足 3NF；重点分析 orders 为什么 total_price 只存舱价(不冗余航司等)；
       flight 冗余 region_dep/region_arr 的取舍(方便按地区查询、避免频繁 join，保持更新一致性可控)
4.3 给出核心建表 SQL 3~4 段（sys_user、flight、orders，含 CHECK 约束、唯一索引、外键说明）

## 第五章 数据库物理设计（5 分）
5.1 存储引擎：InnoDB（事务、行级锁、外键支持）理由
5.2 字符集：utf8mb4（支持中文与 emoji）理由
5.3 索引设计：列出 8 个关键索引及其服务的查询（idx_feature=flight(code,datetime_dep) 唯一、
       flight(region_dep,region_arr,datetime_dep)、orders(id_user)、orders(id_flight)、orders(code) 唯一、
       route(id_flight) 唯一、sys_user(username) 唯一、airport(region)），并给一条建索引 SQL
5.4 事务与并发控制：订票用 SELECT...FOR UPDATE 行锁 + 事务，给一条加锁 SQL 并说明如何防超卖
5.5 数据安全与备份：权限分离、Flyway 版本化迁移、MySQL 定期备份策略(文字即可)

## 第六章 系统实现与关键 SQL
6.1 技术栈与分层架构（DDD：interfaces→application→domain→infrastructure，SQL 只在基础设施层）
6.2 关键功能 SQL 附录（每个功能给真实 SQL）：
   - 航班搜索(动态条件+分页)
   - 订票(加锁扣座+插订单)
   - 我的订单(只能查自己的 WHERE id_user=?)
   - 退订退款(动态计算 refund=max(0,总价-退票费))
   - 三统计：热门航班销量Top10(COUNT+SUM(CASE WHEN)+GROUP BY)、营收总览(整表聚合)、旅客消费排行Top10(JOIN+GROUP BY)
6.3 演示数据规模与统计口径说明（175 实体 / 374 关联关系；成交金额=已支付/已退款订单金额之和）
```
